## Pipelines

- [01_issue](01_issue/CONTEXT.md): from open issue to reviewed pull request
  - [01_worktree](01_issue/stages/01_worktree/CONTEXT.md): create the worktree and branch for the issue and record them.
  - [02_issue_body](01_issue/stages/02_issue_body/CONTEXT.md): turn the issue into a run card with one proof line per acceptance criterion.
  - [03_prove_red](01_issue/stages/03_prove_red/CONTEXT.md): show on unfixed code that each testable criterion fails.
  - [04_implement](01_issue/stages/04_implement/CONTEXT.md): make the red proof green with the smallest change and commit it.
  - [05_docs_sync](01_issue/stages/05_docs_sync/CONTEXT.md): bring help, schema, README and docs in line with the change.
  - [06_pr](01_issue/stages/06_pr/CONTEXT.md): push the branch, open the PR against the base and write the report.
- [02_research](02_research/CONTEXT.md): from a hard question to a binding decision
  - [01_question](02_research/stages/01_question/CONTEXT.md): state the question, the overlapping issues and the numbered premises to test.
  - [02_method](02_research/stages/02_method/CONTEXT.md): decompose the question and gather primary sources, tagging every claim.
  - [03_premise](02_research/stages/03_premise/CONTEXT.md): measure each premise with a small Rust test or an existing log.
  - [04_decision](02_research/stages/04_decision/CONTEXT.md): write the decision: scope split, spec and measurable acceptance criteria.
  - [05_issue_comment](02_research/stages/05_issue_comment/CONTEXT.md): post the decision as one issue comment and write the report.
- [03_orchestrate](03_orchestrate/CONTEXT.md): from open tickets to merged branches
  - [01_wave_plan](03_orchestrate/stages/01_wave_plan/CONTEXT.md): choose the tickets of this wave so that no two touch the same file.
  - [02_brief](03_orchestrate/stages/02_brief/CONTEXT.md): write the brief of each ticket from the template.
  - [03_dispatch](03_orchestrate/stages/03_dispatch/CONTEXT.md): start one agent per brief and record who runs what.
  - [04_watchdog](03_orchestrate/stages/04_watchdog/CONTEXT.md): start the silence watcher over the agents' worktrees.
  - [05_receive_and_verify](03_orchestrate/stages/05_receive_and_verify/CONTEXT.md): compare each agent's report with PR state, git and gate logs.
  - [06_merge_cleanup](03_orchestrate/stages/06_merge_cleanup/CONTEXT.md): merge verified PRs into the base and remove only finished tickets' leftovers.
- [04_gate](04_gate/CONTEXT.md): one full gate on the integration tip
  - [01_targeted_tests](04_gate/stages/01_targeted_tests/CONTEXT.md): collect the targeted-test evidence of every ticket in the gate.
  - [02_integration_merge](04_gate/stages/02_integration_merge/CONTEXT.md): confirm that all gate tickets are merged into the integration branch.
  - [03_full_gate](04_gate/stages/03_full_gate/CONTEXT.md): run the CPU suite, the CUDA suite and the tiny benchmark once on the base tip.
  - [04_tested_vs_merged](04_gate/stages/04_tested_vs_merged/CONTEXT.md): show that nothing but docs changed after the gate.
  - [05_merge_main](04_gate/stages/05_merge_main/CONTEXT.md): on the project lead's written instruction, merge the integration pull request into main and report.
- [05_diagnose](05_diagnose/CONTEXT.md): from a stuck or diverging GPU run to a classified cause
  - [01_prove_stuck](05_diagnose/stages/01_prove_stuck/CONTEXT.md): measure whether the process is stuck or only slow.
  - [02_stack](05_diagnose/stages/02_stack/CONTEXT.md): capture function and line of every thread of the stuck process.
  - [03_wait_graph](05_diagnose/stages/03_wait_graph/CONTEXT.md): build the wait-for graph and list every cycle before touching code.
  - [04_repro_red](05_diagnose/stages/04_repro_red/CONTEXT.md): reproduce the hang in a small test that fails on the unfixed code.
  - [05_fix_bounded](05_diagnose/stages/05_fix_bounded/CONTEXT.md): fix the cause and bound every wait so a future bug fails with a message.
  - [06_medium_run](05_diagnose/stages/06_medium_run/CONTEXT.md): run the real path on a medium store in under 10 minutes.
  - [07_classify_deltas](05_diagnose/stages/07_classify_deltas/CONTEXT.md): give every parity delta a class and an owner.
- [06_data](06_data/CONTEXT.md): from raw market files to a verified, leak-checked store
  - [01_acquire](06_data/stages/01_acquire/CONTEXT.md): download spot files from the vendor archive and verify every checksum.
  - [02_import_prep](06_data/stages/02_import_prep/CONTEXT.md): build the store from the raw files.
  - [03_panel_pit](06_data/stages/03_panel_pit/CONTEXT.md): build point-in-time membership and the panel, keeping delisted coins.
  - [04_enrich](06_data/stages/04_enrich/CONTEXT.md): append features to the store and prove the device path matches the CPU.
  - [05_audit_lockbox](06_data/stages/05_audit_lockbox/CONTEXT.md): audit for leakage and show that the 2026H2 lockbox is refused.
  - [06_verify_manifest](06_data/stages/06_verify_manifest/CONTEXT.md): verify the manifest against the data and write the report.
- [07_longrun](07_longrun/CONTEXT.md): from merged work to an audited multi-hour run
  - [01_preconditions](07_longrun/stages/01_preconditions/CONTEXT.md): prove that the run may start now.
  - [02_launch](07_longrun/stages/02_launch/CONTEXT.md): launch the run through the tracked launcher.
  - [03_monitor](07_longrun/stages/03_monitor/CONTEXT.md): show that the run is alive and writing its log and checkpoints.
  - [04_resume](07_longrun/stages/04_resume/CONTEXT.md): resume a stopped run from its checkpoint.
  - [05_audit](07_longrun/stages/05_audit/CONTEXT.md): audit the finished run with independent auditors.
  - [06_report](07_longrun/stages/06_report/CONTEXT.md): report the result with baselines and the honest result fields.
- [08_close](08_close/CONTEXT.md): from merged code to a closed issue and a clean checkout
  - [01_verifier](08_close/stages/01_verifier/CONTEXT.md): map each acceptance criterion to named evidence and post the verdict.
  - [02_close](08_close/stages/02_close/CONTEXT.md): close the issue after a CLOSE verdict.
  - [03_cleanup](08_close/stages/03_cleanup/CONTEXT.md): remove this ticket's worktree and branches and nothing else.
- [09_handoff](09_handoff/CONTEXT.md): from live state to a safe restart
  - [01_state](09_handoff/stages/01_state/CONTEXT.md): collect the state of PRs, branches, worktrees, gates and processes.
  - [02_status](09_handoff/stages/02_status/CONTEXT.md): write the status message from the state file.
  - [03_memory](09_handoff/stages/03_memory/CONTEXT.md): update the memory file with branch contents, running tickets and the queue.
  - [04_handoff_file](09_handoff/stages/04_handoff_file/CONTEXT.md): write HANDOFF.md for the next session.
  - [05_restart_check](09_handoff/stages/05_restart_check/CONTEXT.md): prove the repository and the machine are in the recorded state.
- [10_machine](10_machine/CONTEXT.md): share the desktop with the agents
  - [01_lock](10_machine/stages/01_lock/CONTEXT.md): show that heavy processes run at the lowest priority behind the lock.
  - [02_pause](10_machine/stages/02_pause/CONTEXT.md): create the pause file so no new run queues.
  - [03_measure](10_machine/stages/03_measure/CONTEXT.md): measure load, GPU use and the top consumers.
  - [04_priority](10_machine/stages/04_priority/CONTEXT.md): act on processes you started, ask about everything else.
  - [05_resume](10_machine/stages/05_resume/CONTEXT.md): remove the pause file and report.
